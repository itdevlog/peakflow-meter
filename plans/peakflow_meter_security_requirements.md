# Требования к безопасности и конфиденциальности медицинских данных

## 1. Общие положения

Система "Пикфлоуметр" обрабатывает персональные данные и медицинскую информацию, что требует строгого соблюдения норм по защите персональных данных и медицинской конфиденциальности. Ниже приведены требования, которые должны быть реализованы в системе.

## 2. Нормативно-правовая база

Система должна соответствовать следующим нормативным актам:

- Федеральный закон "О персональных данных" №152-ФЗ
- Приказ Минздрава России от 26.07.2021 №472н "Об утверждении стандарта медицинской помощи"
- Приказ Минкомсвязи России от 18.07.2017 №622 "Об утверждении Требований к защите персональных данных"
- Общий регламент по защите данных (GDPR) в части, применимой к международному использованию системы

## 3. Классификация данных

### 3.1. Категории обрабатываемых данных

#### Персональные данные:
- Идентификационные данные: ФИО, дата рождения
- Контактная информация: email, Telegram ID
- Данные профиля: пол, рост, возраст
- Идентификаторы в системе: ID пользователей

#### Медицинские данные:
- Результаты измерений пикфлоуметра
- История измерений
- Заметки к измерениям
- Классификация по зонам (зеленая/желтая/красная)

#### Данные аутентификации:
- Хешированные пароли
- JWT-токены
- Данные сессий

## 4. Требования к аутентификации и авторизации

### 4.1. Аутентификация
- Обязательная многофакторная аутентификация (MFA) для родительских аккаунтов
- Использование JWT-токенов с ограниченным сроком действия (1 час для access token, 7 дней для refresh token)
- Хеширование паролей с использованием bcrypt с минимальным cost factor 12
- Регулярное обновление токенов
- Блокировка аккаунта после 5 неудачных попыток входа в течение 15 минут

### 4.2. Авторизация
- Ролевая система доступа (RBAC):
  - Родитель: полный доступ к своим данным и данным своих детей
  - Ребенок: доступ только к своим измерениям и профилю
- Проверка принадлежности данных пользователю при каждом запросе
- Разграничение доступа к API-эндпоинтам в зависимости от роли

## 5. Защита данных

### 5.1. Шифрование
- Шифрование данных в покое: AES-256 для хранения чувствительных данных
- Шифрование данных при передаче: TLS 1.3 для всех соединений
- Шифрование конфиденциальных полей в базе данных (например, заметки к измерениям)

### 5.2. Хранение данных
- Данные должны храниться на серверах, расположенных на территории Российской Федерации
- Регулярное резервное копирование с шифрованием
- Удаление данных по истечении срока хранения (5 лет после удаления аккаунта)

### 5.3. Логирование
- Ведение аудит-логов всех операций с персональными данными
- Логирование попыток несанкционированного доступа
- Хранение логов безопасности не менее 1 года
- Защита логов от несанкционированного изменения

## 6. Безопасность API

### 6.1. Защита от атак
- Rate limiting: ограничение количества запросов (100/час на пользователя)
- CSRF-защита для веб-интерфейса
- Валидация и очистка всех входных данных
- Защита от SQL-инъекций через ORM
- Защита от XSS-атак через экранирование вывода

### 6.2. Управление доступом
- Использование CORS только для разрешенных доменов
- Проверка токенов аутентификации для всех защищенных эндпоинтов
- Использование Content Security Policy (CSP)

## 7. Безопасность Telegram-бота

### 7.1. Аутентификация пользователей
- Сопоставление Telegram ID с аккаунтом в системе через привязку
- Проверка подписи вебхуков от Telegram
- Использование уникального токена для каждого пользователя

### 7.2. Защита данных
- Минимизация передачи конфиденциальной информации через Telegram
- Шифрование конфиденциальных сообщений
- Не хранение чувствительных данных в переписке Telegram

## 8. Соблюдение медицинской конфиденциальности

### 8.1. Ограничение доступа
- Только авторизованные пользователи имеют доступ к своим данным
- Запрет на передачу данных третьим лицам без явного согласия
- Отсутствие доступа сотрудников системы к медицинским данным пользователей

### 8.2. Уведомления о конфиденциальности
- Четкое информирование пользователей о целях обработки данных
- Предоставление возможности отзывать согласие на обработку данных
- Уведомление о любых инцидентах безопасности в течение 72 часов

## 9. Права субъектов персональных данных

Система должна обеспечивать возможность реализации следующих прав:

- Право на получение информации о своих персональных данных
- Право на исправление неточных данных
- Право на удаление данных ("право на забвение")
- Право на ограничение обработки
- Право на переносимость данных

## 10. Мониторинг безопасности

### 10.1. Инструменты мониторинга
- Регулярный сканирование уязвимостей
- Мониторинг подозрительной активности
- Аудит безопасности не реже 1 раза в год

### 10.2. Реагирование на инциденты
- Процедура реагирования на инциденты безопасности
- Уведомление контролирующих органов при утечке данных
- Резервное копирование для восстановления системы

## 11. Технические меры защиты

- Регулярные обновления программного обеспечения
- Использование WAF (Web Application Firewall)
- Настройка безопасных заголовков HTTP
- Регулярные пентесты и код-ревью
- Использование безопасных конфигураций для всех компонентов системы

## 12. Обучение и осведомленность

- Обучение разработчиков основам безопасности
- Регулярное информирование пользователей о мерах безопасности
- Документирование политик безопасности
